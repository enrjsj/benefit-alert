# Project workflow

The user requests that routine development work include verification, committing,
pushing to GitHub, deployment, and checking the live result without asking again.
Use the existing benefit-alert Vercel project and Render service documented in README.
Do not change the separate cheongyak-one project's services or database.
Never commit credentials. Let Git-triggered deployments run; do not duplicate them.
If automatic deployment is unavailable, deploy the existing service and verify it.
Keep DEVELOPMENT_STATUS.md current and report any verification or access limitations.
